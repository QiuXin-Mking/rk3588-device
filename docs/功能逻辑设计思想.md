# SensorHub 功能逻辑设计思想

## 1. 产品定位

SensorHub 是运行在 RK3588 设备本机上的数据采集终端界面，目标硬件为 5.5 英寸、1920×1080 的固定式触摸屏。

它不是桌面管理后台，也不是手持手机应用。设计目标是让操作人员站在设备前，用尽量少的步骤完成设备检查、任务选择、数据采集和记录管理。

## 2. 核心设计原则

### 2.1 设备优先，而不是分辨率优先

1920×1080 只代表像素数量，不代表屏幕很大。界面尺寸以 5.5 英寸实体屏幕上的可读性和可触控性为准：

- 高频操作必须拥有足够大的触控区域。
- 正文和状态文字不能按照桌面网页字号设计。
- 重要操作不能依赖鼠标悬停。
- 不能为了显示更多信息而持续缩小文字和按钮。

### 2.2 横屏优先，竖屏兼容

- 1920×1080 横屏是主要使用形态。
- 横屏页面应尽量在一屏内完成主要任务。
- 1080×1920 竖屏作为兼容模式，可以在明确区域内滚动。
- 不使用手机端“所有内容从上到下堆叠”的方式直接适配横屏。

### 2.3 页面不整体滚动

设备安装位置固定，整页滚动不适合持续操作：

- 页面根节点保持固定，不产生整体滚动。
- 记录、Wi-Fi、蓝牙设备、任务选项等长数据只在各自列表内部滚动。
- 主要操作按钮保持在稳定位置，不随列表内容移动。
- 弹窗内部数据过多时，仅弹窗内容区滚动。

### 2.4 一个页面只解决一个主要任务

一级导航分为四个稳定入口：

| 一级页面 | 主要职责 |
|---|---|
| 任务 | 任务广场、筛选、任务详情、SOP 和任务承接 |
| 采集 | 三套设备状态与预览、标零、录制控制和采集日志 |
| 数据 | 管理本地与后台采集记录及验收、上传状态 |
| 我的 | 展示 Mango 设备状态与预览摘要 |

设备端和移动端必须保持同样的四页和功能归属；移动端可以在页面内部重排，但不得合并或拆分一级页面。管理员保护的 Wi-Fi、蓝牙、设备和设置能力不占用新的一级入口。

### 2.5 导航层级必须明确

- 一级页面顶部显示 `Logo + 当前页面标题`。
- 二级页面顶部用 `返回按钮 + 当前页面标题` 替代 Logo。
- 页面内部不再重复占用一整行显示相同标题和无操作价值的描述。
- 可进入二级页面的区域必须提供文字、箭头或按钮等明确提示，不能只依赖“整张卡片可以点击”的猜测。

### 2.6 业务状态以设备后台为准

设备连接、录制状态、文件状态和系统状态以 `server.js` 返回的数据为准：

- 设备状态和录制状态每 3 秒刷新。
- 文件列表每 5 秒刷新。
- 录制、预览、连接、校准、解码、传输和删除操作完成后主动刷新相关状态。
- 前端不自行伪造设备已经成功完成的状态。

后台离线时，界面保留导航和本地页面能力，同时明确显示设备离线，不让整个前端因单次请求失败而不可操作。

### 2.7 原系统能力必须保持可用

React 重构只替换前端表现层，不改变原有设备控制逻辑。以下能力继续调用原后台接口：

- 设备、电量、存储和连接状态。
- 摄像头实时预览。
- 开始和停止录制。
- 本地文件列表、预览、解码、传输和删除。
- Wi-Fi 扫描、连接和断开。
- 蓝牙扫描、连接和断开。
- 手套校准服务与左右手校准交接。
- 录制后自动处理设置。

所有设备调用集中在 `frontend/src/services/deviceApi.ts`，页面组件不直接复制请求逻辑。

## 3. 主要业务流程

### 3.1 数据采集流程

1. 在“任务”页按场景、发布时间、项目和子任务筛选任务。
2. 查看任务详情和 SOP，填报位置、可选 GPS、附近位置、对象数量与目标物体后领取。
3. 在“采集”页检查头戴六目、左腕单目、右腕单目的摄像头和 IMU 状态并切换预览。
4. 按提示完成标零，开始或停止录制；记录同步后台后结束任务。
5. 在“数据”页按项目、任务、子任务、套件、数据 ID、地点、时间、验收和数据状态管理记录。
6. 管理后台对上报记录进行验收，形成完整闭环。

### 3.2 Wi-Fi 流程

1. 显示当前连接状态。
2. 扫描附近网络。
3. 选择网络。
4. 加密网络打开触屏密码键盘。
5. 提交 SSID 和密码到后台。
6. 成功后刷新设备状态；失败则保留当前页面并提示原因。
7. 已连接网络可执行断开操作。

### 3.3 蓝牙与校准流程

1. 展示左右手套的有线和蓝牙连接状态。
2. 扫描附近蓝牙设备。
3. 连接或断开目标设备。
4. 管理校准服务的启动、停止和重启。
5. 根据左右手及传输方式启动校准。
6. 跳转到校准器页面完成校准。
7. 返回终端后停止校准交接并恢复采集服务。

### 3.4 记录管理流程

1. 获取本地录制目录列表。
2. 显示记录数量、数据总量和外接存储状态。
3. 打开记录详情。
4. 根据记录内容显示彩色、深度、双目、手套、IMU 和音频标签。
5. 支持生成预览、手动解码、传输至外接存储和删除。
6. 删除属于不可恢复操作，执行前需要二次确认。

## 4. 前端状态边界

### 后台权威状态

- 硬件在线状态。
- 录制和预览状态。
- Wi-Fi、蓝牙和手套状态。
- 文件及外接存储状态。
- 校准服务状态。
- 录制后自动处理设置。

### 前端本地状态

- 当前页面和返回历史。
- 主题、语言和沉浸模式。
- 弹窗开关和当前选项。
- 触屏键盘大小写及符号层。
- 尚未接入后台的任务筛选临时选择。

本地状态不能覆盖后台权威状态，也不能把占位流程显示成后台已成功处理。

## 5. 异常与反馈原则

- 请求进行中时，阻止同一操作被重复触发。
- 硬件条件不满足时禁用对应按钮，并展示原因。
- 操作失败保留用户当前页面和已输入内容。
- 成功、失败和待接入状态都使用明确文字反馈。
- 长名称使用省略或局部换行，不能撑破固定布局。
- 大量数据通过局部滚动、截断和详情页面处理。

## 6. 主题与语言

- 默认支持浅色和深色主题。
- 浅色主题用于改善部分 TFT 屏幕的黑色表现和户外可读性。
- 相机画面等需要对比度的区域可以保持深色。
- 中文和英文共用同一套功能结构。
- 英文文本较长时优先缩短文案、限制宽度或换行，不能整体缩小所有字号。

## 7. 占位功能原则

设计稿中存在但后台尚未支持的功能，可以提前完成页面和操作位置，但必须满足：

- 明确标注“待接入”“预留”或“接口未支持”。
- 点击后只展示说明，不伪造成功结果。
- 不影响已有真实功能。
- 后续接入接口时只替换数据和动作层，不重新设计页面结构。

详细缺口见 [前端已实现但后台未支持的功能.md](./前端已实现但后台未支持的功能.md)。
